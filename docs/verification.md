# 验证记录与 Windows 验收清单

## 本次环境

- macOS arm64，.NET SDK 10.0.401。
- Windows 桌面项目目标：`net10.0-windows`；发布架构：`win-x64`。
- 未连接 Windows 桌面环境，因此原生 UI、截图、托盘通知、DPI 和锁屏行为尚未实机验证。

## 已执行的自动化验证

`dotnet build ScreenWatch.slnx -c Release`：0 警告、0 错误。

`dotnet run --project tests/ScreenWatch.Core.Tests -c Release --no-build`：22/22 通过。

自包含单文件发布成功：`artifacts/publish/win-x64/ScreenWatch.exe`。文件类型检查为 `PE32+ executable (GUI) x86-64, for MS Windows`，发布目录仅包含这一个 EXE。

离线演示页面已提供；本次浏览器工具无法打开本地文件 URL（浏览器安全策略阻止），因此演示页交互也未声称完成浏览器实测。

测试覆盖：

- 相同图片、相反颜色、轻微像素差异和局部状态块变化。
- RGB 颜色差异，不因灰度接近误判成相同颜色。
- 单帧闪烁、连续命中、持续画面不重复提醒、消失后重新触发。
- 冷却边界和冷却期间已经消失的画面不补发。
- 单调时间退回保护。
- 多显示器负坐标、越界和大尺寸区域。
- 配置往返保存、原子替换、非法设置不破坏原配置、损坏配置保留原文。
- 参考图片路径校验和未来配置版本拒绝。

测试使用可跨平台运行的真实核心算法和配置文件读写。没有把截图 API 或 Windows UI 的模拟结果作为已验证的运行行为。

## Windows 真机验收（待执行）

在普通 Windows 10/11 x64 用户会话中解压便携包，建议先使用 `demo/index.html`。

| 步骤 | 预期 |
| --- | --- |
| 双击 EXE，且电脑没有额外安装 .NET | 中文主窗口打开，系统托盘有图标 |
| 再启动一次 EXE | 提示已经运行，不建立第二个监控实例 |
| 显示演示页“已完成”，框选整张状态卡 | 坐标与尺寸正确；框选层关闭后恢复主窗口 |
| 按 Esc / 右键取消框选 | 原区域与参考图片保持不变 |
| 保存当前画面为参考并手动测试 | 参考预览正确，测试相似度接近 100%，不触发通知 |
| 切换到“等待中”并手动测试 | 低于默认阈值 95% |
| 冷却设为 3 秒，演示页自动切换，开始监控 | 主窗口隐藏，“已完成”连续两次命中后提醒一次并保存截图 |
| 让“已完成”保持超过冷却时间 | 不重复提醒；经两次“等待中”后再次完成可重新提醒 |
| 双击托盘、右键停止、右键退出 | 分别停止并显示主窗口、停止、真正结束进程 |
| 修改参数，退出并重启 | 区域、参考图和参数恢复，启动时不自动监控 |
| 选择新区域 | 原参考失效，须重新保存或导入图片 |
| 导入错误尺寸或损坏图片 | 明确报错，原参考不被覆盖 |
| 在 100%、150%、200% 缩放显示器分别框选 | 实际截图与选择区域一致，界面无不可操作按钮 |
| 副显示器位于主显示器左侧，选择负坐标区域 | 正确截图与匹配 |
| 监控中锁屏、断开远程桌面、休眠恢复、改变分辨率 | 停止监控，回到桌面后需手动开始 |
| 把目标浏览器最小化或用其他窗口遮挡 | 最近匹配基于实际屏幕内容，不应被理解为仍在读取原网页 |
| 关闭声音和命中截图后匹配 | 仍记录命中，不播放提示音、不生成新的命中截图 |
| 开启 Windows“请勿打扰” | 即使气泡被系统隐藏，也能从日志和截图确认命中 |

Windows runner 的构建工作流已提供，但没有在本次环境中触发或宣称运行通过。
